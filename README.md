# org-ops — 評価制度・組織運営アプリ

役割・目標・数字・報告のルールを1か所にまとめ、**チーム全員が同じ記録を見ながら**会社を運営するためのアプリです。

- **アプリ**：https://urahama8810.github.io/org-ops/
- **使い方の動画**：https://urahama8810.github.io/org-ops/guide.html （ナレーション付き・約17分）

インストールは不要です。上のアドレスを開くだけで、パソコンでもスマートフォンでも使えます。
データはそれぞれのブラウザの中、または会社の共有フォルダ・共有サーバーに保存されます。
このリポジトリには、会社の実データは一切入っていません。

---

## 使い方

### まず「わたしの画面」から

初めて開いたら、**自分の名前を選びます**。すると、その人に関係するものだけが表示されます。

- 今週やること（期限が過ぎた対策、まもなく確認日の仕事、まだの1on1）
- 自分が担当しているKPIと、今週の実績
- 任されている仕事と、次の確認日
- 自分の役割・成果物・決めてよいこと・承認が必要なこと

選んだ人の情報は**そのパソコンにだけ**保存されます。ほかの人には見えず、あとから変更できます。

多くのメンバーは、この画面だけ見ていれば足ります。

### 会社全体を見る

管理職・経営に関わる人は「会社全体」も見ます。記入の抜け、期限の遅れ、決めていない条件を、
日々の記録から自動で洗い出して並べます。上から順に片づけると、下の項目も一緒に消えます。

## 会社のメンバーと共有する（3つの方法）

「設定・データ」→「みんなで同じデータを使う」で切り替えます。

### ①このパソコンのみ（初期設定）
データはこのブラウザの中だけ。1人で使う場合。

### ②共有フォルダ（おすすめ）
会社のOneDrive・SharePoint・Googleドライブなど、**全員のパソコンで同期されているフォルダ**を選ぶだけ。
サーバーも登録も不要です。

1. 全員が同じアプリのアドレスを開く
2. 「設定・データ」→「②共有フォルダ」→「共有フォルダに接続」
3. 会社の共有フォルダを選ぶ（初回だけ）

保存のたび、および15秒ごとに自動で同期します。同時に編集した場合は、どちらを残すか確認画面が出ます。

> Chrome / Edge で動きます。Safari と Firefox は未対応のため、その場合は③を使ってください。

### ③共有サーバー
社外や自宅からも同じデータを見たい場合。`server/` に Cloudflare Workers 用のコードがあります。
無料枠で動きます。手順は [server/README.md](server/README.md) を参照してください。

## 最初にやること

1. 「設定・データ」で会社名と、この取り組みの進行役（1名）を入力する
2. 「社員・役割台帳」でメンバーを登録する（**最初は7項目だけ**でかまいません）
   - 氏名／部署／直属の上司／役割／成果物／KPI／承認が必要なこと
   - 残り（雇用形態・等級・引き継ぎ先など）はあとから足せます
3. 「会社・部門目標」で目標を3〜5個決める（責任者と、基準にする数字を必ず決める）
4. 「職種別役割表」で標準8職種を作成し、自社に合わせて直す
5. 週次KPI会議を始める

迷ったら「会社全体」の**次の一手**が、次にやることを1つだけ示します。

## 運用サイクル

| いつ | 何を | 画面 |
|---|---|---|
| 毎週 | KPI会議（45分）。未達には対策・担当者・期限をその場で決める | 週次KPI会議 |
| 毎週 | 任せた仕事の中間確認 | 仕事の任せ方 |
| 毎月 | 全員と1on1（30分）。前回決めたことの結果を先に確認する | 月次1on1 |
| 四半期 | 評価（自己 → 上司 → 調整 → 確定 → 本人説明） | 四半期評価 |
| 四半期 | お金の使い道（4つの数字を写すだけ） | お金の使い道 |
| 半年 | 振り返り質問と、6つの数字の推移を確認 | 組織の健康診断 |
| その都度 | よくない情報・遅延・クレームの報告、重要な決定の登録 | 報告・承認ルール／重要な決定 |

会議は**45分（10分：数字／20分：原因／10分：対策・担当者・期限／5分：経営判断）**で区切ります。
決まらない議題は持ち帰らず、経営判断事項として記録します。

## この会社で決めている運用ルール

### 仕事を渡すときの6項目
① 期待する成果物・数値　② 期限　③ 本人が決めてよい範囲
④ やってはいけないこと　⑤ **中間確認日**　⑥ 困ったときの相談先

⑤が空欄だと、渡したあとの状況が見えないまま期限を迎えがちです。
期日が過ぎると「会社全体」に赤で出ます。

うまくいかなかったときは、本人だけでなく**渡し方のほう**も一緒に見直します。

### 重要な決定は24時間おく
人の配置、契約の解除、大きな支出、法的な対応。あとから戻しにくい決定は、
登録してから24時間おいて確定します。その間に：

- 反対の立場から意見を言う人を1名決めて、意見を記録する
- 「いま決めないと失うもの」と「急いで決めて外したときに失うもの」を両方書く

この4つがそろって、はじめて確定できます。急ぐ場合は記録を残したうえで手順を飛ばせますが、
その事実も記録に残ります。**このルールは役職に関係なく全員に同じように当てはまります。**

### 新しい取り組みは1枚にまとめて48時間おく
目的／期待する成果／必要な人・お金・時間／うまくいかないと判断する条件／
**撤退の条件**／責任者／使ってよい上限。撤退の条件は始める前に決めます。

### 利益は先に本業へ戻す枠を取る
人材・営業・商品・仕組みへ戻す割合を先に決めてから、残りの使い道を判断します。
入力は四半期に一度、会計ソフトから4つの数字を写すだけです。

### 社外の関係者とは、始める前に取り決める
相手が得たいこと／決めてよい範囲／責任と成果物／データの扱い／金額／**終わり方**。
終わり方は、もめてからでは決められません。

## 自動で行われる判定

日々の記録から、次のようなことを自動で洗い出して「会社全体」に並べます（全45種類）。

- 台帳の記入漏れ（直属の上司・成果物・KPI・承認事項）
- 未達なのに対策・担当者・期限が空欄のKPI
- 期限を過ぎた対策、報告期限を守れなかった案件、承認待ち
- 途中の確認日が決まっていない仕事、確認日を過ぎた仕事
- 待ち時間が明けた決定、反対意見の確認が済んでいない決定
- 撤退の条件が決まっていない取り組み
- 契約・合意が文書化されていない関係者、定期確認の期日超過
- 1人が直接みる人数が目安（4〜6人）を超えている
- これからの役割をまだ話せていないメンバー
- 本業へ戻す割合が目標に届いていない、事業と関係ない支出が上限を超えている

**個人を名指しで評価するような指摘は出しません。** 記入が足りない状態や、
手順が済んでいない状態として表示します。

## 個人情報の扱いについて

このアプリは全員が同じデータを見るため、**個人の値踏みにあたる項目は持ちません**。

- 給与・年収の欄はありません（会計・労務側で管理してください）
- 「離職リスクの見立て」のような主観的な評価項目はありません
- 決定の記録に、そのときの心理状態を残す項目はありません
- 自己評価を書いている段階では、上司の評価と調整メモは表示されません
  （先に見えると自己評価が引きずられ、突き合わせる意味がなくなるため）

評価の点数と根拠は共有データに含まれます。共有フォルダ・共有サーバーを使う場合は、
**誰がそのフォルダにアクセスできるか**を確認してから設定してください。

## 出力

- **CSV**：社員台帳／目標／役割表／週次KPI／1on1／評価／報告／改善計画／任せた仕事／重要な決定／新規の企画書／関係者／お金の使い道（「全データをCSVで書き出す」で13本まとめて）
- **印刷**：各画面の右上「印刷」。評価シート・議事録・1on1記録は個別に印刷できます
- **バックアップ**：「設定・データ」→「バックアップを保存（JSON）」

---

## データの保存場所

| 共有方法 | 保存先 |
|---|---|
| このパソコンのみ | ブラウザの localStorage（キー `hyokaSeido_v1`） |
| 共有フォルダ | 選んだフォルダの `org-ops-data.json` |
| 共有サーバー | Cloudflare Workers KV |

いずれの場合も、**週に1回はバックアップをファイルに保存**してください。
ブラウザの履歴を消すとデータも消えます。

なお、次の3つは共有データに含まれず、そのパソコンにだけ残ります。

- 「わたしの画面」で選んだ人（`hyokaSeido_me`）
- 画面の明るさの設定（`hyokaSeido_theme`）
- はじめての案内を読んだかどうか（`hyokaSeido_intro_v2`）

## 注意（制度面）

評価制度を**減給・賞与・降格などに連動させる前に**、就業規則・賃金規程との整合や
必要な手続きを社労士等に確認してください。

導入初期は「評価を正確に運用できること」を優先し、報酬への反映は急がないことをおすすめします。
「設定・データ」→「評価を給与に結びつける前に」で、確認済みかどうかを記録できます。

## 開発者向け

### 構成

```
org-ops/
├── src/
│   ├── index-template.html   HTMLの骨組み（__CSS__ / __JS__ を差し替える）
│   ├── styles.css            スタイル1枚（CSS変数でトークン化・ダークモード対応）
│   └── js/
│       ├── 00-icons.js       線画アイコン（インラインSVG）
│       ├── 01-core.js        定数・データ構造・保存/読込
│       ├── 01b-structure.js  運用ルールの定義データ
│       ├── 02-ui.js          共通部品（モーダル・フォーム・表・通知）
│       ├── 03-logic.js       判定ロジック（アラート45種）
│       ├── 04-dashboard.js   会社全体
│       ├── 04b-me.js         わたしの画面
│       ├── 05〜19            各画面
│       ├── 20-sync.js        共有（フォルダ／サーバー）
│       └── 99-app.js         ナビ・画面切替・起動
├── build.ps1                 単一HTMLに結合
├── publish.ps1               GitHub Pages へ公開
├── dist/                     ビルド結果
├── docs/                     GitHub Pages の配信元
├── guide/                    使い方の動画（生成物と生成ツール）
├── server/                   共有サーバー（Cloudflare Workers）
└── test/                     自動テスト（Node.js、依存パッケージなし）
    ├── all.js                すべての検査をまとめて実行（ビルド前に自動で走る）
    ├── dom.js                検査用の簡易ブラウザ（本物に近い挙動）
    ├── sweep.js              総当たり検査（全画面×全データ×全ボタン）
    ├── wiring-test.js        押しても無反応のボタンを探す
    ├── dataloss-test.js      操作で記録が減らないかを見張る
    ├── roundtrip-test.js     入れた値が本当に保存されるかを往復で確かめる
    ├── render-test.js        画面・ロジック・保存・共有
    ├── player-test.js        動画プレイヤー
    └── server-test.js        共有サーバーのAPI
```

依存パッケージはありません。素のJavaScript（ES5相当）です。

**画面の追加**：`VIEWS.キー = { title, desc, render() }` を定義し、`99-app.js` の `NAV` に追加します。
**操作の追加**：`action('名前', fn)` で登録し、HTML側に `data-act="名前"` を書きます（イベント委譲）。

> ⚠️ `build.ps1` の JS 結合順は `[StringComparer]::Ordinal` で並べています。
> PowerShell の `Sort-Object Name` は日本語環境だとハイフンを軽く扱うため、
> `04-dashboard.js` と `04b-me.js` の前後が入れ替わり、`VIEWS` が未定義になります。

### ビルド

```powershell
.\build.ps1
```

`src/` の CSS と JS を1つのHTMLにまとめて `dist/` に出力します。

### 公開

```powershell
.\publish.ps1
```

ビルド → `docs/` へコピー → コミット → push まで行います。GitHub Pages が自動で更新します。

### テスト

**まとめて実行（これだけ覚えれば十分）**

```bash
node test/all.js
```

`build.ps1` はビルドの前にこれを自動で実行します。
1件でも失敗すると**ビルドは中止**され、`dist/` は古いまま守られます。
つまり「直したつもりが別のところを壊していた」状態のファイルは、公開まで進めません。

**個別に実行**

```bash
node test/render-test.js    # 画面・ロジック・保存・共有（161件）
node test/player-test.js    # 動画プレイヤーの再生ロジック（15件）
node test/server-test.js    # 共有サーバーのAPI（11件）
node test/wiring-test.js    # 押しても無反応のボタンを探す（454個）
node test/dataloss-test.js  # 操作で記録が減らないか（279回）
node test/roundtrip-test.js # 入れた値が本当に保存されるか（18通り）
node test/sweep.js          # 総当たり検査（約2,300通り）
```

#### 総当たり検査（test/sweep.js）について

観点を思いつく限り並べる方式は、思いつかなかった観点が抜けます。
そこで sweep.js は**観点に頼らず機械的に全部試します**。

| 何を | どこまで |
|---|---|
| 全画面 × 全データ状態 | 18画面 × 9状態（空・サンプル・0・負の値・巨大値・null混入・配列が壊れている等）＋ タブ全通り |
| 画面のボタン | 表示されている全ボタンを実際にクリック（313個） |
| 入力ふきだし | 全種類を開いて、保存ボタンまで押す（30種類。評価5段階・決定5段階・委任4状態を含む） |
| 文字のエスケープ | 全項目に細工文字5種を入れて、タグとして解釈されないか（90通り） |
| 計算関数 | 25関数に境界値（0・負・巨大・空文字・null・NaN）を総当たり（1,641通り） |
| 画面の作り | id の重複、キーボードで押せない操作 |

画面や項目を増やすと**自動的に検査対象も増えます**。追記は要りません。

#### test/dom.js について

検査用の簡易ブラウザです。本物に近づけてあるのが要点で、特に:

- `querySelector` は**要素が無ければ null を返す**（従来の模擬は必ず何かを返すため、
  「画面に無い欄を読んで落ちる」不具合を素通りさせていました）
- クリックが**親要素へ伝わる**（`data-act` のイベント委譲を本物と同じ経路で検証できます）
- HTMLを実際に解析して木構造を作る

この2点が無かった頃、「評価シートが保存できない」不具合を161件のテストが全部見逃していました。

すべて Node.js の標準機能だけで動きます。`render-test.js` は `vm` でアプリのJSを読み込み、
最小限のDOMモックで全画面を描画して例外が出ないことを確認します。

主な検証内容：

- 全画面が描画でき、全ナビ項目に対応する画面がある
- 評価点の加重平均、KPIの状態判定、報告期限の判定
- 24時間ルール・48時間ルールの判定
- 決定の記録に心理状態を残す項目がないこと
- 社員台帳に給与・離職リスクの項目がないこと
- 指摘の文面に、特定の人を評価する語が混ざらないこと
- 指摘の文面に内部IDが混ざらないこと
- 保存 → 読込でデータが保持され、古い形式や壊れたJSONでも起動すること

### レクチャー動画の作り直し

```powershell
.\guide\tools\make-guide.ps1              # 撮影からやり直す（約6分）
.\guide\tools\make-guide.ps1 -SkipShoot   # 撮影済み画像から組み立て直すだけ
```

台本は `guide/tools/scenario.js`（59コマ）。1要素が1コマで、`setup` で画面を作り、
`highlight` で強調範囲を指定し、`say` がナレーション原稿です。

ヘッドレスEdge（またはChrome）で1440×810のスクリーンショットを撮り、
Base64で埋め込んだ単一HTMLのプレイヤーを生成します。
ナレーションはブラウザの音声合成（Web Speech API）で再生時に読み上げます。

### データ構造

`emptyData()`（`01-core.js`）が正です。古い形式のデータは `mergeDefaults()` で
不足項目を補うため、項目を増やしても既存データは壊れません。

## バージョン

**v3.0.0** — 全員で使う前提に合わせて、表現・機能・デザインを全面的に見直しました。

- 「わたしの画面」を新設（自分に関係するものだけを表示）
- 個人の値踏みにあたる項目を削除（給与・離職リスクの見立て・決定時の心理状態）
- 特定個人の行動分析にあたる画面と文言をすべて削除・書き換え
- ナビゲーションを使用頻度順に再編（5グループ17項目。90日の導入計画はホームから開く）
- 社員台帳の追加を7項目に、お金の入力を四半期4項目に簡素化
- デザインをCSS変数でトークン化、線画アイコンを導入、ダークモード対応
- 入力途中の取り消し確認、キーボード操作、フォーカス表示に対応
- 自己評価の段階では上司評価を表示しないよう変更
