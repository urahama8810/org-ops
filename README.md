# org-ops — 評価制度・組織管理体制 運用アプリ

「評価制度・組織管理体制 90日導入プロジェクト指示書」（2026年8月 初版）と、
「企業成長を阻害する『負のシステム』構造分析レポート」（2026年8月）を、
そのまま社内で運用するためのアプリ。

**目的**：社長個人の記憶・感覚・監視に依存せず、役割・数字・権限・報告ルールで組織を運営できる状態をつくる。
あわせて、**放置と過剰統制の振り子**を止め、継続的なマネジメントへ移行する。

---

## 使い方

### 開く

ブラウザで次のアドレスを開くだけです。インストール・登録は要りません。

- アプリ　　　　： https://urahama8810.github.io/org-ops/
- 使い方レクチャー： https://urahama8810.github.io/org-ops/guide.html

社内のメンバーには、このアドレスをそのまま伝えてください。
パソコン（Chrome / Edge 推奨）でもスマートフォンでも開けます。

オフラインで使いたい場合は、`dist/評価制度・組織管理アプリ.html` をダブルクリックしても同じものが動きます。

### 初めての人へ

先に **使い方レクチャー**（ナレーション付き・約16分／57コマ）を見てもらってください。

- 再生／一時停止、前後のコマ送り、シークバー、再生速度の変更
- 「目次」ボタンから見たい場所へジャンプ
- 「ナレーション」ボタンで音声の入／切。右の欄で読み上げる声を選べます
- キーボード：スペース＝再生／一時停止、←→＝前後のコマ、F＝全画面
- **ナレーションを最後まで読み終えてから次のコマへ進みます**（途中で切れません）

ナレーションはブラウザの読み上げ機能を使っています。

- インターネットに接続していると、Edge の自然な日本語音声（Nanami）で読み上げます。
- 接続していない場合は、パソコンに入っている音声（Haruka など）に自動で切り替わります。
- 音声が使えないパソコンでは、自動的に字幕だけの再生になります（画面下に案内が出ます）。
- 音が出ないときは、パソコンの音量と、ブラウザのタブがミュートになっていないかを確認してください。

## 会社のメンバーと共有する（3つの方法）

「設定・データ」→「会社のメンバーと共有する」で選びます。

| 方法 | 向いている場面 | 準備 |
|---|---|---|
| ①このパソコンのみ | 1人で使う | 不要（既定） |
| **②共有フォルダ（おすすめ）** | 社内の全員で同じデータを使う | 会社の共有フォルダを1つ選ぶだけ |
| ③共有サーバー | 社外・自宅からも同じデータを使う | サーバーを1回だけ設置（下記） |

### ②共有フォルダ

OneDrive・SharePoint・Googleドライブなど、**全員のパソコンで同期されているフォルダ**を選ぶだけです。
サーバーも登録も費用も要りません。

1. 全員が同じ共有フォルダを、それぞれのパソコンで同期しておく
2. アプリの「共有フォルダに接続」を押して、そのフォルダを選ぶ
3. フォルダ内に `org-ops-data.json` が作られ、全員がこれを読み書きします

- 誰かが入力すると、15秒ほどで他の人の画面にも反映されます
- 同時に編集して食い違った場合は確認画面が出るので、「相手の内容を取り込む」か「自分の内容で上書きする」を選びます
- Chrome / Edge で動きます（Safari・Firefox は非対応）

### ③共有サーバー

社外や自宅からも使いたい場合に、Cloudflare Workers（無料枠）へ置き場所を作ります。

```powershell
server\deploy.ps1
```

ブラウザで1回だけ Cloudflare にログインすれば、あとは自動です。
終わるとアドレスと合言葉が表示されるので、アプリの「設定・データ」に入力してください。
くわしくは `server/README.md`。

## 最初にやること

1. 「設定・データ」で会社名・代表者・**社内プロジェクト責任者（1名）**・開始日を入力する
2. 「社員・役割台帳」に全社員を登録する（空欄を放置しない）
3. 「会社・部門目標」で会社目標を3〜5個決める
4. 「職種別役割表」で「標準8職種を作成」を押し、自社に合わせて修正する
5. 「週次KPI会議」で今週の会議を作成する

操作を試したいだけなら、ダッシュボードの「操作を試す（サンプルデータを入れる）」でサンプル会社のデータが入ります。
※ 本番運用を始める前に、必ず「全データを削除」してから入力してください。

## 「負のシステム」への対策（v2で追加した部分）

構造分析レポートの中心にある指摘は、次の1行です。

> **「管理」は避けるが、「支配」は強める。**
> 平時は放置し、問題が見えた瞬間だけ強く介入するため、問題の予防も人材育成も起きない。

これを止めるために、次の4つを仕組みとして入れました。

### 1. 委任カード（任せ方の6項目）

任せるときに、①期待する成果物・数値 ②期限 ③本人が決めてよい範囲 ④やってはいけないこと
⑤**中間確認日** ⑥困った時の相談先と報告条件 — を決めてから渡します。

⑤が空欄だと「任せた」ではなく「放置」になります。期日が過ぎるとダッシュボードに赤で出ます。
終了時には、本人の資質ではなく **任せ方の設計** も検証します。

### 2. 意思決定の防波堤（24時間ルール／48時間ルール）

- 人事・解約・大型支出・訴訟方針などは、登録から **24時間** 確定できません
- 「強い怒り・焦り・不信がある」で登録した決裁は、落ち着いて見直すまで確定できません
- 反対意見を言う役割を1人指名し、その意見を記録しないと確定できません
- 「今すぐ決めない損失」と「衝動的に決める損失」の両方を書かないと確定できません
- 新規案件は1枚企画書（目的・期待利益・必要資源・失敗条件・撤退条件・責任者・資源上限）を書いて **48時間** 保留

ルールを破って確定することもできますが、その場合は「冷却期間を守らずに確定」として記録され、診断に反映されます。

### 3. 資本配分と関係者ガバナンス

- 利益に対する**再投資率を先取り**で決め、人材・営業・商品・仕組みへの投資を実績で追います
- 事業と関係ない支出には年間上限と承認者を設定します
- スポンサー・共同事業者・外注先は、相手の利害・権限・責任・知的財産・**撤退条件**を文書にします
  （「信頼できる人だから契約不要」ではなく「信頼を長く維持するために契約する」）

### 4. 経営の健全度診断

- **90日で追うべき先行指標**（情報流通・育成・人材定着・営業・資本配分・意思決定）を、入力済みの記録から自動計算
- **5つの強化ループ**（育成放棄／優秀者流出／営業・再投資回避／ガバナンス崩壊／低基準固定）のリスクを判定
- **検証質問19問**（レポート第13章）に答えると、上流3指標の警告が出ます
- 結果は日付付きで記録でき、90日後に推移を見返せます

## 自動で行われる判定

- 台帳の記入率、直属上司が未確定の社員、成果物・KPIが未定義の社員、社長だけが把握している社員
- 直属部下が上限（既定6名）を超える管理者
- 会社目標が3〜5個に収まっているか、責任者と「正とするデータ」があるか
- 週次KPI会議の未実施、未達項目で対策・担当者・期限が空欄のもの、期限超過の対策
- 当月の1on1未実施者、未完了の「翌月の約束」
- 報告期限（24時間以内／当日中／事前承認）の遵守判定
- 評価の進行状況、評価者ごとの平均点の差（甘辛）
- 評価1、または評価2が2期連続 → 改善計画が必要
- 報酬連動をONにしているのに就業規則の確認が未完了
- **中間確認日が未設定／期日超過の委任、6項目が埋まっていない委任**
- **冷却期間が明けた決裁、反対意見が未確認の決裁、撤退条件のない新規案件**
- **契約が未文書の関係者、相手の利害が未記入、定期確認の期日超過**
- **再投資率が目標未達、非事業支出が年間上限超過**
- **離職リスクが高いのに将来像を示せていない社員**

## 出力

- 全画面の印刷（印刷用レイアウトに自動で切り替わります）
- 1on1記入シート（手書き用の空欄シート）の印刷
- CSV書き出し（12種類）：社員台帳・目標・職種表・週次KPI・1on1・評価・報告・改善計画・委任カード・重大決裁・新規案件の企画書・関係者台帳・資本配分
  「設定・データ」→「全データをCSVで書き出す」で一括、各画面の「CSV」ボタンで個別に出せます
- 全データのJSONバックアップ／復元

## データの保存場所

入力したデータは、選んだ共有方法によって次の場所にあります。

- ①このパソコンのみ … 開いたブラウザの中（localStorage）
- ②共有フォルダ … 会社の共有フォルダ内の `org-ops-data.json`（＋各自のブラウザ内に控え）
- ③共有サーバー … 自分たちで設置した Cloudflare Workers の保管領域（＋各自のブラウザ内に控え）

いずれの場合も、**週に1回は「バックアップを保存」でJSONファイルを残してください。**
ブラウザの履歴・キャッシュを削除すると、ブラウザ内のデータは消えます。

## 注意（制度面）

評価制度を**減給・賞与・降格等へ連動させる前に**、就業規則・賃金規程との整合や必要な手続を社労士等へ確認してください。
制度導入初期は「評価を正確に運用できること」を優先し、報酬変更を急がないでください。

虚偽報告・無断契約・資金流出・データ持出し等は、通常の評価や改善計画ではなく、
規程・法的手続に基づいて別に扱ってください。

健全度診断は心理・医学上の診断ではなく、経営実務上のモデルです。
実際の社員面談、退職理由、営業データ、会議記録、投資判断と照合して修正しながら使ってください。

```
│     ├ 18-capital.js      資本配分・関係者ガバナンス

│     ├ 20-sync.js         共有（このPC／共有フォルダ／共有サーバー）
│     └ 99-app.js          ナビゲーション・画面切替・起動
├ test/
│  ├ render-test.js                    ← 描画・ロジックの自動テスト

├ build.ps1                            ← 単一HTMLへの結合
└ README.md
```

- 依存パッケージなし。素のJavaScript（ES5相当の書き方）で、ビルドツールも不要。
- 画面は「カード」と「タイル」で組む。`.grid` の中に複数のカードを縦に積むときは `<div class="col">` で包むと、
  列の下端がそろう（最後のカードが伸びる。カードが1枚だけの列は伸ばさない）。
- タイルの中でボタンを下端にそろえたいときは `<div class="foot">` に入れる。
- 画面が820px以下になると、左のメニューは上部の横並びに変わる（スマートフォンでも全画面へ移動できる）。
- JSは**ファイル名の昇順**で結合されるため、追加する画面は番号付きのファイル名にする。
- 画面を追加するときは `VIEWS.キー = { title, desc, render:function(){ return HTML文字列; } }` を定義し、`99-app.js` の `NAV` に項目を足す。
- ボタン等は `data-act="名前"` を付け、`action('名前', function(dataset, element){ ... })` で処理を登録する（イベント委譲）。
- 画面内にタブを持たせる場合は `VIEWS.キー.setTab = function(t){ ... }` を定義すると、他画面から `data-act="go" data-view="キー" data-tab="..."` で開ける。

### ビルド

```powershell
.\build.ps1
```

`src/` の CSS と JS を `dist/評価制度・組織管理アプリ.html` にまとめます。

> `*.ps1` は日本語を含むため **BOM付きUTF-8** で保存すること（Windows PowerShell 5.1 がBOMなしUTF-8をANSIとして読み、文字化けするため）。

### 公開

```powershell
.\publish.ps1
```

`dist/` と `guide/` の成果物を `docs/` にコピーし、コミットして GitHub へ push します。
GitHub Pages（main ブランチの `/docs`）から配信されます。

`player-test.js` は、レクチャーの読み上げが途中で切れないことを検証します。

- 台本の全ナレーションが、1回あたり40文字以内に分割されること（分割しても文字が欠けないこと）
- 読み上げ中は次のコマへ進まない作りであること、固まった場合の打ち切り上限があること
- 「1on1」「KPI」など読み間違いやすい語が、読みで書かれていること

`server-test.js` は、共有サーバーを実際に配置しなくても、合言葉の確認・保存・競合の判定を検証します。

画面やロジックを直したら、`build.ps1` の前にこれを実行してください。

### レクチャー動画の作り直し

```powershell
guide\tools\make-guide.ps1              # 撮影からやり直す（約10分）
guide\tools\make-guide.ps1 -SkipShoot   # 撮影済み画像から組み立て直すだけ（数秒）
```

`dist/` のアプリ本体に `narrator.js` と `scenario.js` を注入し、ヘッドレスEdgeで1コマずつ撮影して、
画像を1つのHTML（プレーヤー）に埋め込みます。説明を足したいときは `scenario.js` にコマを追加するだけです。

ハマりどころ：

- **スクロールした状態は撮影できない**（ヘッドレスEdgeは白紙になる）。そのため `narrator.js` の `__bring()` は
  `scrollIntoView` を使わず、`#view` や `.modal-body` の上マージンで内容を押し上げている。
- Edge は正常終了時も stderr にログを出すため、`$ErrorActionPreference = 'Stop'` のままだと撮影ループが止まる。
- 撮影後、コマ画像が 25KB 未満だと「要確認」と表示される（白紙・空振りの検知）。
- ナレーションは音声ファイルを持たず、再生時にブラウザの音声合成（Web Speech API）で読み上げる。
  そのため原稿を直しても `-SkipShoot` の組み立て直しだけで反映され、ファイルサイズも増えない。
  原稿は `scenario.js` の `say:`（読み間違い防止のため「1on1」→「ワンオンワン」のように読みで書く）。
- **ナレーションの途中切れ対策**（v2で修正）：
  - 原稿は句読点で40文字程度に分割して読ませる（1回の発話が長いとブラウザが打ち切るため）
  - 読み上げが終わるまで次のコマへ進まない（時間ではなく `onend` で送る。固まった場合だけ大きめの上限で打ち切る）
  - 再生中は8秒ごとに `pause()`→`resume()` を入れる（Chrome / Edge が長時間の読み上げを勝手に止める既知の不具合への対策）
  - 一時停止は `cancel()` で止め、再生時は読んでいた文から読み直す
- mp4 が必要な場合は ffmpeg があれば変換できる：
  `ffmpeg -f concat -safe 0 -i list.txt -vsync vfr -pix_fmt yuv420p -c:v libx264 out.mp4`
  （`list.txt` に `file 'frames/000.png'` と `duration 5` を交互に並べる。秒数は `scenario.js` の `sec`）

### データ構造

`localStorage` のキー `hyokaSeido_v1` に単一のJSONで保存。
共有の設定は別キー `hyokaSeido_sync_v1`（同期でデータが往復しないよう本体と分けている）。
保存済みデータに新項目が増えても `mergeDefaults()` が既定値で補完するため、旧データのまま新版を開いても壊れません。
